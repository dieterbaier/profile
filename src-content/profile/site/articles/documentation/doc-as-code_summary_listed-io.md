## title

Dokumentation als Teil der Softwareentwicklung

## summary

Docs-as-Code bedeutet nicht, dass Code die Dokumentation ersetzt.

Code kann zeigen, was ein System tut. Aber er erklärt nicht automatisch, warum Entscheidungen getroffen wurden, welche Anforderungen wichtig waren oder welche Sicht ein Product Owner, ein Projektleiter oder ein externer Dienstleister braucht.

Der eigentliche Wert von Docs-as-Code liegt darin, Dokumentation wie Software zu behandeln: strukturiert, versioniert, automatisiert und möglichst nah am Code. Wenn Dokumentation im gleichen Arbeitsfluss entsteht, sinkt der Medienbruch. Wenn sie aus einer Quelle in verschiedene Formate generiert werden kann, bleibt sie nutzbarer.

Das Ziel ist nicht mehr Dokumentation um der Dokumentation willen. Das Ziel ist Dokumentation, die im Entwicklungsprozess lebt.
