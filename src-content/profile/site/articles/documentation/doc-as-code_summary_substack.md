## title

Dokumentation als Code

## subtitle

Warum Docs-as-Code keine Tool-Frage ist, sondern eine Arbeitsweise für nachhaltige Softwaredokumentation.

## summary

Dokumentation scheitert selten daran, dass Menschen grundsätzlich nicht dokumentieren wollen. Sie scheitert oft daran, dass der Prozess nicht zu ihrem Arbeitsalltag passt.

Der Artikel räumt mit zwei verbreiteten Mythen auf: Code allein ist keine vollständige Dokumentation, und Dokumentation ist nicht zwangsläufig veraltet, sobald sie geschrieben wurde. Beides hängt stark davon ab, wie Dokumentation in den Entwicklungsprozess eingebettet ist.

Docs-as-Code bedeutet dabei nicht, dass Code die Dokumentation ersetzt. Es bedeutet, Dokumentation mit denselben Prinzipien zu behandeln wie Software: klare Struktur, Versionierung, Automatisierung, Wiederverwendung und eine Build-Pipeline, die unterschiedliche Ausgabeformate erzeugen kann.

Besonders wichtig ist der Gedanke „write once, deliver anywhere“: dieselbe Quelle kann als Website, PDF oder zielgruppenspezifische Sicht ausgeliefert werden. Dadurch wird Dokumentation nicht zur lästigen Zusatzaufgabe, sondern zu einem natürlichen Bestandteil professioneller Softwareentwicklung.
