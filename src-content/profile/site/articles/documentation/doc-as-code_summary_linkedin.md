## title

Docs-as-Code heißt nicht: Code ersetzt Dokumentation.

## summary

„Mein Code ist die Dokumentation“ funktioniert nur in sehr engen Grenzen. Code kann zeigen, was ein System tut. Aber er erklärt selten ausreichend, warum es so gebaut wurde, welche Entscheidungen dahinterstehen und welche Sicht unterschiedliche Stakeholder brauchen.

Docs-as-Code bedeutet für mich deshalb nicht, Dokumentation einfach neben den Code zu legen. Es bedeutet, sie wie Software zu behandeln:

- strukturiert
- versioniert
- automatisiert
- nah am Entwicklungsprozess
- aus einer Quelle in mehrere Formate auslieferbar

Gerade Architekturdokumentation braucht Kontext, Entscheidungen und nachvollziehbare Zusammenhänge. Wenn Dokumentation ohne Medienbruch entsteht und über eine Pipeline als Website, PDF oder andere Sicht generiert werden kann, wird sie deutlich wahrscheinlicher gepflegt.

Dokumentation ist kein Nebenprodukt der Softwareentwicklung. Sie ist Teil davon.
