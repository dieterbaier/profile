Das `profile-dieterbaier`-System hat folgende **Geschäftliche Wechselwirkungen**:

| Wechselwirkung | Beschreibung | Richtung | Häufigkeit |
|---------------|--------------|----------|------------|
| **Inhaltspflege** | Dieter Baier bearbeitet AsciiDoc-Dateien | → System | Hoch (täglich/wöchentlich) |
| **README-Deployment** | Automatisches Hochladen der READMEs zu GitHub/GitLab | System → | Bei Änderungen |
| **Website-Deployment** | Automatisches Hochladen der Website | System → | Bei Änderungen |
| **Architektur-Deployment** | Automatisches Hochladen der Architektur-Dokus | System → | Bei Änderungen |

== Technischer Kontext

=== Eingaben (Inputs)

[cols="1,2,1", options="header"]
|=== 
|Typ |Beschreibung |Format 

|**AsciiDoc-Quelldateien** 
|Alle Inhalte (Profil, CV, Projekte, Architektur) 
|`.adoc` 

|**Theme-Dateien** 
|CSS, JavaScript, Assets für Präsentation 
|`.css`, `.js`, `.png`, `.ico` 

|**Build-Konfiguration** 
|Gradle-Skripte und Eigenschaften 
|`.gradle`, `.properties` 

|**Environment-Variablen** 
|Sensible Daten (Kontaktdaten für CV) 
|`.env` 

|**Docker-Image** 
|Runtime-Umgebung mit allen Tools 
|Docker Image 

|===

|**Pandoc** 
|Konvertierung von DocBook nach Markdown 
|Aktuelle 
|System (Docker-Image) 

|**Graphviz** 
|Generierung von Diagrammen (PlantUML) 
|Aktuelle 
|System (Docker-Image)

|Build-Orchestrierung 
|8.x

|Runtime für Asciidoctor

|System (Docker-Image)

|Aktuelle 
|GitHub Actions

== Einfluss auf andere Architekturentscheidungen

=== Verweise auf Entscheidungen

| Kontext-Element | Architekturentscheidung | Begründung |
|----------------|------------------------|------------|
| AsciiDoc als Input-Format | <<decisions/ADR-001-use-asciidoc.adoc,ADR-001: Use AsciiDoc>> | Zentrale Entscheidung für das Format |
| Gradle als Build-Tool | <<decisions/ADR-002-use-gradle.adoc,ADR-002: Use Gradle>> | Orchestrierung der Verarbeitung |
| Docker für Runtime | <<decisions/ADR-003-use-docker.adoc,ADR-003: Use Docker>> | Bereitstellung der Tools |
| Pandoc für Markdown | <<decisions/ADR-004-use-pandoc.adoc,ADR-004: Use Pandoc>> | Konvertierung für READMEs und Artikel-Exporte |
| SFTP für Deployment | (implizit in Pipeline) | Hosting der Outputs |

=== Verweise auf Qualitätsanforderungen

| Kontext-Element | Qualitätskriterium | Priorität | Begründung |
|----------------|-------------------|----------|------------|
| Externe Tools (Pandoc, Graphviz) | Reproduzierbarkeit | ⭐⭐⭐⭐⭐ | Docker-Container stellt Tools bereit |
| GitHub Actions | Automatisierbarkeit | ⭐⭐⭐⭐⭐ | CI/CD-Pipeline |
| SFTP-Deployment | Zuverlässigkeit | ⭐⭐⭐⭐ | Deployment muss funktionieren |
| Docker-Image | Wartbarkeit | ⭐⭐⭐⭐ | Image muss aktuell gehalten werden |

=== Verweise auf Bausteine

| Kontext-Element | Baustein | Beziehung |
|----------------|----------|-----------|
| AsciiDoc-Dateien | Content (AsciiDoc) | Input |
| Theme-Dateien | Themes | Input |
| Gradle-Skripte | Gradle Build | Konfiguration |
| Docker-Image | Docker-Container | Runtime |
| GitHub Actions | GitHub Actions | CI/CD |
