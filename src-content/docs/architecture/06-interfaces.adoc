== Übersicht der Schnittstellen

Das System hat **interne Schnittstellen** (zwischen den Bausteinen) und **externe Schnittstellen** (zu anderen Systemen).
Jede Schnittstelle hat ein **klar definiertes Protokoll** und **Verantwortlichkeiten**.

[.text-center]
[plantuml]
----
@startuml
left to right direction

title Schnittstellen-Übersicht

package "Interne Schnittstellen" as internal {
  [AsciiDoc → Asciidoctor]
  [Gradle → Docker]
  [Gradle → Pandoc]
  [Gradle → Assets]
}

  [Docker → Host FS]
  [GitHub Actions → Docker]
  [GitHub Actions → SFTP]
  [GitHub Actions → GitHub API]
}

internal -[hidden]-> external

@enduml

== 1. Interne Schnittstellen

=== 1.1 AsciiDoc → Asciidoctor

[cols="1,2,1,1", options="header"]
|=== 
|Aspekt |Beschreibung |Richtung |Protokoll 

|**Verantwortung** 
|Konvertierung von AsciiDoc nach HTML/PDF 
|Content → Asciidoctor 
|Asciidoctor Gradle Plugin 

|**Input** 
|AsciiDoc-Dateien (`*.adoc`) 
|Content → Asciidoctor 
|Dateisystem 

|**Output** 
|HTML-Dateien (`*.html`) oder PDF 
|Asciidoctor → Output 
|Dateisystem 

|**Konfiguration** 
|Asciidoctor-Attribute (Backend, Stylesheets) 
|Gradle → Asciidoctor 
|Gradle Task 

|**Abhängigkeiten** 
|Asciidoctor Java Bibliothek 
|– 
|Maven Central 

|=== 

**Beispiel:**
```groovy
asciidoctor {
    attributes(
        'stylesheet': 'style.css',
        'stylesdir': 'stylesheet',
        'backend': 'html5'
    )
}
```

* **Verwendet von:** <<05-building-blocks,Baustein Gradle Build>>
* **Implementiert durch:** <<decisions/ADR-001-use-asciidoc.adoc,ADR-001: Use AsciiDoc>>
* **Beeinflusst durch:** <<07-quality-requirements,Qualitätsanforderung Korrektheit>>

=== 1.2 Gradle → Docker

[cols="1,2,1,1", options="header"]
|=== 
|Aspekt |Beschreibung |Richtung |Protokoll 

|**Verantwortung** 
|Ausführung von Gradle in isolierter Umgebung 
|Host → Docker 
|Docker CLI 

|**Input** 
|Gradle-Kommando (z. B. `buildAll`) 
|Host → Docker 
|Command-Line 

|**Output** 
|Build-Ergebnisse im gemounteten Volume 
|Docker → Host 
|Dateisystem 

|**Volumes** 
|`/app` (Working Directory) 
|Host ↔ Docker 
|Volume Mount 

|**Umgebungsvariablen** 
|Secrets (SITE_*, CONTACT_*) 
|Host → Docker 
|Environment Variables 

|=== 

**Beispiel:**
```bash
docker run --rm \
  -v $(pwd):/app \
  -v $HOME/.gradle:/root/.gradle \
  -e SITE_EMAIL \
  -e CONTACT_STREET \
  -w /app \
  ghcr.io/docs-as-code-toolkit/docs-toolbox:v1.1.0 \
  ./gradlew buildAll
```

=== 1.3 Gradle → Pandoc

[cols="1,2,1,1", options="header"]
|=== 
|Aspekt |Beschreibung |Richtung |Protokoll 

|**Verantwortung** 
|Konvertierung von DocBook nach Markdown 
|Gradle → Pandoc 
|Command-Line 

|**Input** 
|DocBook-Datei (`*.xml`) oder DocBook-Verzeichnis (`**/*.xml`) 
|Gradle → Pandoc 
|Dateisystem 

|**Output** 
|Markdown-Datei (`*.md`) oder Markdown-Verzeichnis (`**/*.md`) 
|Pandoc → Gradle 
|Dateisystem 

|**Konfiguration** 
|Pandoc-Parameter (Format, Wrapper) 
|Gradle → Pandoc 
|Command-Line Args 

|**Abhängigkeiten** 
|Pandoc installiert im Docker-Image 
|– 
|Docker-Image 

|=== 

**Beispiel:**
```groovy
task convertDocBookToMarkdown(type: Exec) {
    commandLine 'pandoc',
        inputFile,
        '-f', 'docbook',
        '-t', 'gfm',
        '--wrap=none',
        '-o', outputFile
}

tasks.register('buildArticlesMarkdown', PandocDirectoryTask) {
    setInputDirectory(layout.buildDirectory.dir("articles/docbook"))
    setOutputDirectory(layout.buildDirectory.dir("articles"))
}
```

=== Verweise
* **Verwendet von:** <<05-building-blocks,Baustein Gradle Build>>

[cols="1,2,1,1", options="header"]

|**Verantwortung** 
|Kopieren von Theme-Dateien in Output-Verzeichnis 
|Themes → Output 
|Gradle Copy-Task

|Copy-Task in Gradle

        include "*.css"

        into "assets/icons"
    }
}
```

=== 2.1 Docker → Host Filesystem

[cols="1,2,1,1", options="header"]
|=== 
|Aspekt |Beschreibung |Richtung |Protokoll 

|**Verantwortung** 
|Bereitstellung von Dateien für den Container 
|Host → Docker 
|Volume Mount 

|**Mount Points** 
|`/app` (Working Directory) 
|Host ↔ Docker 
|Volume Mount 

|**Berechtigungen** 
|Lesen/Schreiben für Container 
|Host → Docker 
|Filesystem Permissions 

|**Caching** 
|`.gradle`-Verzeichnis 
|Host ↔ Docker

      -v $HOME/.gradle:/root/.gradle \
      -w /app \
      ghcr.io/docs-as-code-toolkit/docs-toolbox:v1.1.0 \
      ./gradlew buildAll
```

=== 2.3 GitHub Actions → SFTP

[cols="1,2,1,1", options="header"]
|=== 
|Aspekt |Beschreibung |Richtung |Protokoll 

|**Verantwortung** 
|Deployment der Website zu SFTP-Server 
|GitHub Actions → SFTP 
|SFTP 

|**Authentication** 
|Benutzername + Passwort 
|Actions → SFTP 
|GitHub Secrets 

|**Transfer** 
|Upload der Build-Artefakte 
|Actions → SFTP 
|SFTP Protocol 

|**Zielpfade** 
|`/site/` und `/architecture/` 
|Actions → SFTP 
|Server Filesystem 

|=== 

**Beispiel:**
```yaml
- name: Deploy site to private webspace
  run: |
    lftp -u "$SFTP_USER","$SFTP_PASSWORD" sftp://$SFTP_HOST:$SFTP_PORT <<EOF
    set sftp:auto-confirm yes
    mirror -R --delete --verbose ./build/site ${SFTP_REMOTE_BASE}/site
    bye
    EOF
```

=== Verweise
* **Verwendet von:** <<05-building-blocks,Baustein Deployment-Skripte>>
* **Betroffen durch:** <<09-risks-and-constraints,Risiko SFTP-Abhängigkeit>>

=== 2.4 GitHub Actions → GitHub API

[cols="1,2,1,1", options="header"]
|=== 
|Aspekt |Beschreibung |Richtung |Protokoll 

|**Verantwortung** 
|Deployment der READMEs zu GitHub Profil 
|GitHub Actions → GitHub 
|REST API 

|**Authentication** 
|Personal Access Token 
|Actions → GitHub 
|GitHub Secrets 

|**Repository** 
|`dieterbaier/dieterbaier` 
|Actions → GitHub 
|GitHub API 

|**Operationen** 
|Clone, Commit, Push 
|Actions → GitHub 
|Git Protocol 

|=== 

**Beispiel:**
```yaml
- name: update readme on profile repo
  run: |
    cp build/readme/README.md profile/README.md
    cd profile
    git config user.name "github-actions"
    git config user.email "actions@github.com"
    git add README.md
    git commit -m "update README" || echo "no changes"
    git push origin HEAD:main
```

== Einfluss auf andere Architekturentscheidungen

=== Verweise auf Entscheidungen

| Schnittstelle | Architekturentscheidung | Beziehung |
|---------------|------------------------|-----------|
| Gradle → Docker | <<decisions/ADR-003-use-docker.adoc,ADR-003>> | Runtime-Umgebung |
| Gradle → Pandoc | <<decisions/ADR-004-use-pandoc.adoc,ADR-004>> | Tool-Integration |
| GitHub Actions → Docker | <<decisions/ADR-003-use-docker.adoc,ADR-003>> | CI/CD-Integration |

=== Verweise auf Qualitätsanforderungen

| Schnittstelle | Qualitätskriterium | Priorität | Begründung |
|---------------|-------------------|----------|------------|
| AsciiDoc → Asciidoctor | Korrektheit | ⭐⭐⭐⭐⭐ | Conversion muss fehlerfrei sein |
| Gradle → Docker | Reproduzierbarkeit | ⭐⭐⭐⭐⭐ | Gleiches Image → gleiche Ergebnisse |
| Docker → Host FS | Performance | ⭐⭐⭐⭐ | Schnelle I/O-Operationen |
| GitHub Actions → SFTP | Zuverlässigkeit | ⭐⭐⭐⭐ | Deployment muss funktionieren |
| GitHub Actions → GitHub API | Sicherheit | ⭐⭐⭐⭐ | Token-Management |
