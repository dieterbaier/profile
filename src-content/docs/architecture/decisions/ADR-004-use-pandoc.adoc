== Kontext

With our decision to use <<ADR-001-use-asciidoc.adoc,AsciiDoc as the single source format>>, we needed to generate **multiple output formats** for different use cases:

* **HTML** for the website and online CV (via Asciidoctor)
* **PDF** for downloadable CV (via Asciidoctor PDF)
* **Markdown** for GitHub and GitLab READMEs
* **Markdown** exports for articles

While Asciidoctor can generate HTML and PDF directly from AsciiDoc, **Markdown generation is not natively supported**. We needed a solution to convert AsciiDoc to Markdown for the README outputs and reusable article exports.

Two main approaches were considered:

1. **Direct AsciiDoc to Markdown:** Use a tool that converts AsciiDoc directly to Markdown
2. **AsciiDoc → DocBook → Markdown:** Use Asciidoctor to generate DocBook, then convert DocBook to Markdown

=== Optionen

==== Option 1: Asciidoctor.js with Markdown writer

* **Pros:**
  - Direct AsciiDoc to Markdown conversion
  - JavaScript-based, lightweight
  - Part of Asciidoctor ecosystem

* **Cons:**
  - Limited Markdown feature support
  - Less mature than full Asciidoctor
  - JavaScript dependency
  - Limited adoption and documentation

==== Option 2: Pandoc (AsciiDoc → Markdown directly)

* **Pros:**
  - Direct conversion possible
  - Well-known and widely used tool
  - Supports many input/output formats

* **Cons:**
  - AsciiDoc support in Pandoc is **limited** (not all AsciiDoc features are supported)
  - May lose formatting or features during conversion
  - Inconsistent rendering compared to Asciidoctor HTML output

==== Option 3: Asciidoctor → DocBook → Pandoc → Markdown

* **Pros:**
  - Uses **Asciidoctor's full feature set** for initial conversion
  - DocBook is a well-defined intermediate format
  - Pandoc has **excellent DocBook to Markdown support**
  - Most reliable conversion path
  - Preserves most formatting and structure

* **Cons:**
  - Two conversion steps (AsciiDoc → DocBook → Markdown)
  - Slightly more complex build process
  - Requires both Asciidoctor and Pandoc

==== Option 4: Custom Conversion Script

* **Pros:**
  - Tailored exactly to our needs
  - Full control over conversion

* **Cons:**
  - High development effort
  - Maintenance burden
  - Error-prone
  - Not portable

== Entscheidung

We chose **Option 3: Asciidoctor → DocBook → Pandoc → Markdown** for Markdown generation.

**Pugh Matrix Ergebnis:** AsciiDoc→DocBook→Pandoc (+1) schneidet am besten ab, gefolgt von Pandoc Direct (0). Asciidoctor.js (-3) und Custom Script (-4) sind weniger geeignet.

Die Entscheidung für den zweistufigen Ansatz basiert auf der **Feature-Vollständigkeit** und **Konvertierungsqualität**, da Asciidoctor alle AsciiDoc-Features verarbeitet und Pandoc DocBook exzellent nach Markdown konvertiert.

== Konsequenzen

=== Vorteile

Accepted (direct from Pugh analysis)

* Functional Suitability: Feature Completeness: Uses Asciidoctor's full feature set, ensuring all AsciiDoc features are properly processed
* Correctness: Conversion Quality: Pandoc has excellent DocBook to Markdown support
* Maintainability: Consistency: DocBook serves as a stable intermediate format
* Maintainability: Proven Tools: Both Asciidoctor and Pandoc are mature, widely-used tools
* Flexibility: Flexibility: The DocBook intermediate allows for future output formats

=== Nachteile

* Maintainability: Two-Step Conversion: Requires Asciidoctor for first step, Pandoc for second
* Maintainability: Complexity: More complex build configuration
* Performance: Performance: Slightly slower due to two conversion steps
* Compatibility: Tool Dependency: Requires both Asciidoctor and Pandoc in the build environment

== Implementierungsdetails

The conversion process is implemented in `build.gradle`:

```groovy
// 1. Convert AsciiDoc to DocBook
tasks.register('buildReadmeDocbook', org.asciidoctor.gradle.jvm.AsciidoctorTask) {
    setSourceDir(file('src-content/profile/readme'))
    setOutputDir(file('build/readme/docbook'))
    outputOptions {
        backends = ['docbook']
    }
}

// 2. Define Pandoc task
tasks.register('convertDocBookToMarkdown', PandocTask) {
    dependsOn tasks.named('buildReadmeDocbook')
    dependsOn tasks.named('buildReadmeDocbookCopyAssets')
    
    setInputFile(file("build/readme/docbook/README.xml"))
    setOutputFile(file("build/readme/README.md"))
}

// 3. Final HTML build (optional)
tasks.register('buildReadme','convertDocBookToMarkdown','src-content/profile/readme', 'build/readme', [],false)
```

The custom `PandocTask` is defined as:

```groovy
abstract class PandocTask extends DefaultTask {
    @InputFile
    abstract RegularFileProperty getInputFile()
    
    @OutputFile
    abstract RegularFileProperty getOutputFile()
    
    @TaskAction
    void runPandoc() {
        project.exec {
            commandLine 'pandoc',
                    inputFile.get().asFile,
                    '-f', 'docbook',
                    '-t', 'gfm',
                    '--wrap=none',
                    '--extract-media=build/pandoc/media',
                    '-o', outputFile.get().asFile
        }
    }
}
```

For article exports, the same conversion chain is applied recursively:

```groovy
asciidoctorBase(
    'buildArticlesDocbook',
    '',
    'src-content/profile/site/articles',
    'build/articles/docbook',
    articleSources,
    true,
    'docbook',
    ['type': 'readme']
)

tasks.register('buildArticlesMarkdown', PandocDirectoryTask) {
    dependsOn tasks.named('buildArticlesDocbook')
    dependsOn tasks.named('buildArticlesDocbookCopyAssets')

    setInputDirectory(layout.buildDirectory.dir("articles/docbook"))
    setOutputDirectory(layout.buildDirectory.dir("articles"))
}
```

`PandocDirectoryTask` converts all generated `*.xml` files below `build/articles/docbook` to `*.md` below `build/articles` while preserving the relative article directory structure. Media files are extracted to `build/articles/media`.

Pandoc command options:

* `-f docbook`: Input format is DocBook
* `-t gfm`: Output format is GitHub Flavored Markdown
* `--wrap=none`: No text wrapping
* `--extract-media=...`: Extract media files to specified directory
