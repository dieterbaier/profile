== Kontext

In the context of **Green IT** (sustainable IT practices) and our <<../01-vision-and-goals#_mission_statement,Mission Statement>> of creating an efficient, maintainable documentation pipeline, we faced a fundamental decision about the **design and implementation of our website and CV outputs**.

Modern websites often include numerous third-party components that, while adding convenience or features, come with significant **hidden costs**:

* **Performance Impact:** Third-party scripts (analytics, tracking, social widgets) add weight and slow down page loading
* **Privacy Concerns:** Tracking scripts collect user data without explicit consent
* **Security Risks:** Each third-party dependency is a potential attack vector
* **Environmental Impact:** More data transfer = more energy consumption (data centers, network infrastructure)
* **Maintenance Burden:** Each dependency needs to be updated and monitored
* **User Experience:** Bloated pages are slower and less accessible

Our website serves as a **personal profile and portfolio** – its primary purpose is to **present information clearly and efficiently**, not to track users or maximize engagement metrics.

=== Optionen

==== Option 1: Minimalist Approach (Chosen)

*Use only what is absolutely necessary for the core functionality.*

* **Pros:**
  - Fastest page load times
  - No privacy concerns
  - Minimal security attack surface
  - Lowest environmental impact
  - Easiest maintenance
  - Best accessibility
  - Full control over all components

* **Cons:**
  - No analytics or tracking data
  - No social media integration
  - Less "modern" appearance (no fancy widgets)
  - May lack some convenience features

==== Option 2: Standard Approach

*Include common third-party components (Google Analytics, Font Awesome, etc.).*

* **Pros:**
  - Usage analytics available
  - Access to rich icon libraries
  - Social media sharing buttons
  - "Standard" website features

* **Cons:**
  - Privacy issues (GDPR compliance needed)
  - Performance impact (multiple external requests)
  - Security dependencies
  - Higher environmental footprint
  - Maintenance overhead

==== Option 3: Self-Hosted Components

*Self-host third-party components (e.g., host Font Awesome locally).*

* **Pros:**
  - Maintains privacy (no external tracking)
  - Some performance benefit (no external requests)
  - Still get convenience features

* **Cons:**
  - Larger deployment package
  - Still have maintenance overhead
  - Some environmental impact (larger files)
  - May violate some licenses

== Entscheidung

We chose **Option 1: Minimalist Approach** – using **only what is absolutely necessary** for the website's core functionality.

**Pugh Matrix Ergebnis:** Minimalist (+6) schneidet deutlich besser ab als Standard (-4) und Self-Hosted (+1).

**Core Principle:** If a component doesn't directly serve the purpose of presenting information about Dieter Baier and his work, it is **not included**.

== Konsequenzen

=== Vorteile

Accepted (direct from Pugh analysis)

* Performance: Website loads **extremely fast** (typically < 1s)
* Privacy/Security: **No tracking** of visitors; GDPR-compliant by design
* Security: **Minimal attack surface** (only our own code)
* Sustainability: **Lowest possible environmental impact**
* Maintainability: **No external dependencies** to update or monitor
* Accessibility: **Clean, semantic HTML** without interference from third-party scripts
* Reliability: **Offline Capability:** Website works **completely offline** once loaded
* Maintainability: **Long-term Stability:** No risk of third-party services being discontinued

=== Nachteile

* Performance: No Analytics: We cannot track visitor numbers, page views, or user behavior
* Usability: No Social Features: No built-in social media sharing or follow buttons
* Functional Suitability: Limited Features: Some modern web features (e.g., embedded videos) are excluded
* Maintainability: Manual Maintenance: Some information (e.g., visitor statistics) must be gathered manually

== What This Means in Practice

=== Allowed Components

| Component | Purpose | Justification |
|-----------|---------|---------------|
| **AsciiDoc Content** | Source material | Core functionality |
| **Custom CSS** | Styling | Necessary for presentation |
| **Custom JavaScript** | Minimal interactivity | Only if absolutely necessary (currently none) |
| **Self-Hosted Fonts** | Typography | Improves readability, locally hosted |
| **Self-Hosted Icons** | Visual elements | Improves UX, locally hosted |
| **Static HTML** | Output format | Core functionality |

=== Prohibited Components

| Component | Reason |
|-----------|--------|
| Google Analytics | Tracking, privacy concerns |
| Google Fonts | External request, privacy |
| Font Awesome (CDN) | External request, can be self-hosted |
| jQuery | Unnecessary for simple websites |
| Bootstrap | Unnecessary, adds bloat |
| Social Media Widgets | Tracking, privacy, performance |
| Disqus Comments | Tracking, privacy, performance |
| Any ad networks | Privacy, performance |
| Any tracking pixels | Privacy |

=== Implementation Guidelines

For any new feature or component, ask:

1. **Does this directly serve the purpose of presenting information?** If no → Don't include
2. **Can this be implemented without third-party dependencies?** If yes → Implement directly
3. **Is the performance/privacy/security trade-off worth it?** If no → Don't include

== Concrete Examples

=== Allowed: Self-Hosted Fonts

```css
/* Instead of Google Fonts: */
/* @import url('https://fonts.googleapis.com/css?family=Open+Sans'); */

/* We use: */
@font-face {
    font-family: 'Open Sans';
    src: url('./assets/fonts/OpenSans-Regular.woff2') format('woff2');
}
```

=== Prohibited: Google Analytics

```html
<!-- NOT included: -->
<script async src="https://www.googletagmanager.com/gtag/js?id=GA_MEASUREMENT_ID"></script>
```

=== Allowed: Simple, Self-Written JavaScript

```javascript
// Only if absolutely necessary, e.g. for mobile menu toggle
// Minimal, no dependencies, self-written
document.getElementById('menu-toggle').addEventListener('click', function() {
    document.getElementById('menu').classList.toggle('open');
});
```

=== Prohibited: jQuery

```html
<!-- NOT included: -->
<script src="https://code.jquery.com/jquery-3.6.0.min.js"></script>
```

== Performance Impact

As a result of this decision:

* **Page Weight:** ~50-100 KB (vs. 1-3 MB for typical websites)
* **Requests:** 2-5 (HTML + CSS + maybe JS + fonts) (vs. 20-50+ for typical websites)
* **Load Time:** < 1 second on most connections (vs. 2-5+ seconds)
* **Energy Consumption:** Estimated **90% reduction** compared to average website

== Environmental Impact

According to https://www.websitecarbon.com[Website Carbon Calculator]:

* **Average website:** ~0.5g CO2 per page view
* **Our website:** ~0.01-0.05g CO2 per page view (estimated)
* **Reduction:** ~90-95%

This means for 10,000 page views:

* Average website: ~5 kg CO2
* Our website: ~0.1-0.5 kg CO2
* **Savings: ~4.5-4.9 kg CO2** (equivalent to driving ~25-30 km by car)
