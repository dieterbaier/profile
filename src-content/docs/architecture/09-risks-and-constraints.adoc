== Einleitung

Risiken und Constraints sind **externe oder interne Faktoren**, die den Erfolg des Projekts beeinträchtigen können.
Während **Risiken** potenzielle Probleme beschreiben, die eintreten *könnten*, sind **Constraints** bereits bestehende Einschränkungen, mit denen das Projekt **umgehen muss**.

Dieses Dokument identifiziert und bewertet diese Faktoren und verweist auf **Mitigationsstrategien** und **verwandte Architekturentscheidungen**.

== Constraints (Einschränkungen)

Constraints sind **bestehende Bedingungen**, die das Projekt **akzeptieren und berücksichtigen** muss.

=== 🏗️ Technische Constraints

[cols="1,2,1,1,1", options="header"]
|=== 
|ID |Constraint |Beschreibung |Auswirkung |Verknüpfungen 

|CONSTR-001 
|**AsciiDoc als primäres Format** 
|Das Projekt hat sich für AsciiDoc als Single Source entschieden. 
|- Lernkurve für neue Mitwirkende  
- Abhängigkeit von Asciidoctor 
|<<decisions/ADR-001-use-asciidoc.adoc,ADR-001>>, <<01-vision-and-goals,Mission Statement>> 

|CONSTR-002 
|**Gradle als Build-System** 
|Das Projekt nutzt Gradle für die Build-Orchestrierung. 
|- Java-Abhängigkeit  
- Komplexität für Nicht-Java-Entwickler 
|<<decisions/ADR-002-use-gradle.adoc,ADR-002>>, <<05-building-blocks,Baustein Gradle Build>> 

|CONSTR-003 
|**Docker für Reproduzierbarkeit** 
|Builds müssen in Docker-Containern ausgeführt werden. 
|- Docker muss auf Entwickler-Maschinen verfügbar sein  
- Image-Wartung nötig 
|<<decisions/ADR-003-use-docker.adoc,ADR-003>>, <<05-building-blocks,Baustein Docker-Image>> 

|CONSTR-004 
|**Pandoc für Markdown-Konvertierung** 
|Markdown-Output erfordert Pandoc. 
|- Zusätzliche Abhängigkeit  
- Komplexere Build-Pipeline 
|<<decisions/ADR-004-use-pandoc.adoc,ADR-004>>, <<05-building-blocks,Baustein Docker-Image>> 

|CONSTR-005 
|**GitHub als primäre CI/CD-Plattform** 
|Das Projekt nutzt GitHub Actions für CI/CD. 
|- Abhängigkeit von GitHub  
- Kosten bei vielen Builds 
|<<05-building-blocks,Baustein GitHub Actions>>, <<04-solution-strategy,Strategie Change Detection>> 

|=== 

=== 📁 Projekt-spezifische Constraints

[cols="1,2,1,1,1", options="header"]
|=== 
|ID |Constraint |Beschreibung |Auswirkung |Verknüpfungen 

|CONSTR-101 
|**Persönliche Daten müssen geschützt sein** 
|Kontaktdaten im CV dürfen nicht öffentlich zugänglich sein. 
|- Umgebungsvariablen für private Daten nötig  
- Separate Builds für öffentliche und private Outputs 
|<<05-building-blocks,Baustein Environment Management>>, <<02-stakeholders,ST-002/ST-003>> 

|CONSTR-102 
|**Propietäre Inhalte im Repository** 
|Teile des Inhalts (CV, Projekte) sind proprietär und dürfen nicht open-source sein. 
|- `.gitignore` für sensible Dateien  
- Klare Lizenzierung (MIT für Code, Proprietär für Inhalte) 
|<<05-building-blocks,Baustein Content>>, <<profile-dieterbaier/README.md,Lizenz>> 

|CONSTR-103 
|**Mehrere Deployment-Ziele** 
|Das Projekt deployt zu GitHub, GitLab und SFTP. 
|- Komplexe Deployment-Logik  
- Unterschiedliche API-Anforderungen 
|<<05-building-blocks,Baustein Deployment-Skripte>>, <<06-interfaces,Schnittstellen GitHub Actions → *>> 

|CONSTR-104 
|**Green IT als Projektziel** 
|Das Projekt strebt minimale Ressourcennutzung an. 
|- Change Detection wird zwingend benötigt  
- Optimierung der Build-Prozesse 
|<<decisions/ADR-005-green-it.adoc,ADR-005>>, <<01-vision-and-goals,Sekundäres Ziel Green IT>> 

|===
