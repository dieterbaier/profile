== Übersicht der Bausteine

Das System `profile-dieterbaier` besteht aus **sieben Hauptbausteinen**, die gemeinsam die Dokumentations-Pipeline bilden.
Jeder Baustein hat eine **klare Verantwortung** und interagiert mit anderen Bausteinen über **definierte Schnittstellen**.

[.text-center]
[plantuml]
----
@startuml
left to right direction

title Baustein-Übersicht

package "Content Layer" {
  [Content] as content
  [Themes] as themes
}

package "Build Layer" {
  [Gradle] as gradle
  [Docker] as docker
}

package "Deployment Layer" {
  [GitHub Actions] as github
  [Deployment Scripts] as deploy
}

content --> gradle : "wird verarbeitet durch"
themes --> gradle : "wird genutzt von"
gradle --> docker : "läuft in"
docker --> github : "wird ausgeführt durch"
github --> deploy : "nutzt"

legend right
  | Baustein |
  | Datenfluss |
endlegend

@enduml
----

== 1. Content (AsciiDoc)

=== Verantwortung

* **Zentrale Speicherung** aller Inhalte in AsciiDoc-Format
* **Strukturierte Organisation** der Dokumente (Profil, Projekte, CV, Architektur)
* **Wiederverwendbare Bausteine** durch Includes-Mechanismus

=== Interne Struktur

[.text-center]
[plantuml]
----
@startuml
left to right direction

folder "src-content/" as src {
  folder "profile/" as profile {
    [readme/]
    [cv/]
    [site/]
    [includes/]
  }
  folder "docs/" as docs {
    [arc42/]
    [architecture/]
  }
  folder "theme/" as theme {
    [css/]
    [js/]
    [assets/]
  }
}

src --> profile
src --> docs
src --> theme

@enduml
----

=== Dateistruktur

```
src-content/
├── profile/                    # Persönliche Profile
│   ├── readme/                 # README-Inhalte (GitHub/GitLab)
│   │   └── README.adoc         # Haupt-README (wird zu Markdown konvertiert)
│   ├── cv/                    # CV-Inhalte
│   │   ├── cv.adoc             # Haupt-CV (AsciiDoc)
│   │   └── includes/           # Wiederverwendbare CV-Teile
│   ├── site/                   # Website-Inhalte
│   │   └── index.adoc          # Hauptseite
│   └── includes/               # Gemeinsame Inhalte
│       ├── contact/           # Kontaktdaten (modular)
│       ├── projects/          # Projekte (modular)
│       └── menue.adoc          # Navigation
├── docs/                      # Dokumentation
│   └── arc42/                  # Architektur-Dokumentation (arc42)
│       ├── index.adoc
│       ├── 01_introduction_and_goals.adoc
│       └── ...
│   └── architecture/           # Neue Architektur-Dokumentation
│       ├── index.adoc
│       ├── architecture-canvas.adoc
│       └── ...
└── theme/                     # Präsentation
    ├── style.css              # Haupt-Stylesheet
    ├── theme.js               # JavaScript
    ├── docinfo/               # HTML-Templates
    └── assets/                # Bilder, Icons, Fonts
```

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **Gradle Build** | ← | Wird von Gradle-Tasks gelesen und verarbeitet |
| **Themes** | → | Nutzt CSS/JS aus dem Theme-Verzeichnis |
| **Includes** | ↔ | Referenziert andere AsciiDoc-Dateien |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Strukturierte Organisation** | ⭐⭐⭐⭐⭐ | Klare Verzeichnisstruktur |
| **Wiederverwendbarkeit** | ⭐⭐⭐⭐ | Includes-Mechanismus |
| **Lesbarkeit** | ⭐⭐⭐⭐ | AsciiDoc-Syntax |
| **Versionierbarkeit** | ⭐⭐⭐⭐⭐ | Git-Integration |

=== Verweise

* **Verwendet in:** Alle Build-Tasks
* **Abhängig von:** <<decisions/ADR-001-use-asciidoc.adoc,ADR-001: Use AsciiDoc>>
* **Beeinflusst durch:** <<07-quality-requirements,Qualitätsanforderung Wartbarkeit>>
* **Verknüpft mit:** <<06-interfaces,Schnittstelle AsciiDoc → Asciidoctor>>

== 2. Themes

=== Verantwortung

* **Präsentation** der generierten Dokumente (HTML)
* **Corporate Design** für alle Ausgaben
* **Responsive Layouts** für verschiedene Geräte

=== Interne Struktur

```
theme/
├── style.css                 # Haupt-Stylesheet
├── style-pdf.css             # PDF-spezifische Stile
├── theme.js                  # JavaScript für Interaktivität
├── docinfo/                  # HTML-Templates
│   ├── docinfo.html          # Standard-Header/Footer
│   └── docinfo-*.html        # Spezifische Templates
├── assets/                   # Statische Ressourcen
│   ├── icons/                # SVG/PNG Icons
│   ├── fonts/                # Schriftarten (WOFF2)
│   └── favicon.ico           # Favicon
└── .htaccess                 # Apache-Konfiguration
```

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **Gradle Copy-Tasks** | ← | Wird von Gradle in Output-Verzeichnis kopiert |
| **Asciidoctor** | → | Referenziert CSS/JS in generiertem HTML |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Konsistentes Design** | ⭐⭐⭐⭐⭐ | Einheitliche Stile für alle Outputs |
| **Responsive Design** | ⭐⭐⭐⭐ | Media Queries für mobile Geräte |
| **Performance** | ⭐⭐⭐⭐ | Optimierte CSS/JS-Dateien |
| **Barrierefreiheit** | ⭐⭐⭐ | Semantisches HTML |

=== Verweise

* **Verwendet in:** <<05-building-blocks,Baustein Gradle Build>> (Copy-Tasks)
* **Beeinflusst durch:** <<07-quality-requirements,Qualitätsanforderung Benutzerfreundlichkeit>>
* **Verknüpft mit:** <<06-interfaces,Schnittstelle Gradle → Assets>>

== 3. Gradle Build

=== Verantwortung

* **Orchestrierung** der gesamten Build-Pipeline
* **Task-Management** für verschiedene Output-Formate
* **Dependency Management** für Plugins und Tools

=== Interne Struktur

```
build.gradle          # Haupt-Build-Skript
settings.gradle       # Projekt-Konfiguration
gradle/              # Gradle Wrapper
  └── wrapper/
      ├── gradle-wrapper.jar
      └── gradle-wrapper.properties
```

=== Wichtige Tasks

[cols="1,2,1,1", options="header"]
|=== 
|Task |Beschreibung |Eingaben |Ausgaben 

|**`checkEnvironment`** 
|Prüft verfügbare Tools (Java, Pandoc, Graphviz) 
|System 
|– 

|**`housekeeping`** 
|Bereinigt temporäre Dateien 
|`build/tmp/**` 
|– 

|**`buildReadmeDocbook`** 
|Generiert README als DocBook 
|`src-content/profile/readme/README.adoc` 
|`build/readme/docbook/README.xml` 

|**`convertDocBookToMarkdown`** 
|Konvertiert DocBook zu Markdown (via Pandoc) 
|`build/readme/docbook/README.xml` 
|`build/readme/README.md` 

|**`buildArticlesDocbook`** 
|Generiert Artikel als DocBook 
|`src-content/profile/site/articles/**/*.adoc` 
|`build/articles/docbook/**/*.xml` 

|**`buildArticlesMarkdown`** 
|Konvertiert Artikel-DocBook rekursiv zu Markdown (via Pandoc) 
|`build/articles/docbook/**/*.xml` 
|`build/articles/**/*.md`, `build/articles/media/**` 

|**`buildReadme`** 
|Generiert README als HTML 
|`src-content/profile/readme/README.adoc` 
|`build/readme/README.html` 

|**`buildCVPersonal`** 
|Generiert persönliches CV als PDF 
|`src-content/profile/cv/cv.adoc` 
|`build/cv/cv.pdf` (mit privaten Daten) 

|**`buildCVSite`** 
|Generiert CV für Website als HTML 
|`src-content/profile/cv/cv.adoc` 
|`build/site/cv.html` (ohne private Daten) 

|**`buildCVDownload`** 
|Generiert downloadbares CV als PDF 
|`src-content/profile/cv/cv.adoc` 
|`build/site/cv.pdf` (ohne private Daten) 

|**`buildSite`** 
|Generiert die Website 
|`src-content/profile/site/**` 
|`build/site/**` 

|**`buildArchitecture`** 
|Generiert die Architekturdokumentation 
|`src-content/docs/arc42/**` 
|`build/architecture/**` 

|**`buildAll`** 
|Generiert alle Ausgaben 
|Alle Quellen 
|Alle Outputs 

|=== 

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **Content** | ← | Liest AsciiDoc-Dateien |
| **Themes** | ← | Kopiert Assets in Output-Verzeichnis |
| **Docker** | → | Führt Command-Line-Tools aus |
| **Asciidoctor** | ↔ | Nutzt Asciidoctor Gradle Plugin |
| **Pandoc** | → | Ruft Pandoc über Command-Line auf |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Modularität** | ⭐⭐⭐⭐⭐ | Separate Tasks für jedes Output |
| **Wartbarkeit** | ⭐⭐⭐⭐⭐ | Klare Task-Abhängigkeiten |
| **Erweiterbarkeit** | ⭐⭐⭐⭐ | Einfache Hinzufügung neuer Tasks |
| **Fehlerbehandlung** | ⭐⭐⭐⭐ | Klare Fehlermeldungen |

=== Verweise

* **Implementiert durch:** <<decisions/ADR-002-use-gradle.adoc,ADR-002: Use Gradle>>
* **Beeinflusst durch:** <<07-quality-requirements,Qualitätsanforderung Wartbarkeit>>
* **Verknüpft mit:** <<04-solution-strategy,Strategie Modularer Build>>
* **Verknüpft mit:** <<06-interfaces,Schnittstellen Gradle → Asciidoctor/Pandoc>>

== 4. Docker-Image (docs-toolbox)

=== Verantwortung

* **Bereitstellung** einer reproduzierbaren Runtime-Umgebung
* **Isolation** der Build-Tools von der Host-Umgebung
* **Versionierung** der Tools für Determinismus

=== Technische Details

[cols="1,2,1", options="header"]
|=== 
|Aspekt |Beschreibung |Version 

|**Image-Name** 
|`ghcr.io/docs-as-code-toolkit/docs-toolbox` 
|v1.1.0 

|**Base-Image** 
|Eclipse Temurin (Java) 
|17.x 

|**Enthaltene Tools** 
|Asciidoctor, Pandoc, Graphviz 
|Aktuelle stabile Versionen 

|**Build-Tool** 
|Docker Buildx 
|– 

|=== 

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **GitHub Actions** | ← | Wird als Container ausgeführt |
| **Gradle** | → | Führt Gradle-Tasks aus |
| **Host Filesystem** | ↔ | Mountet `src-content/` und Output-Verzeichnis |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Reproduzierbarkeit** | ⭐⭐⭐⭐⭐ | Gleiches Image → gleiche Ergebnisse |
| **Isolation** | ⭐⭐⭐⭐⭐ | Keine Abhängigkeit von Host-Tools |
| **Wartbarkeit** | ⭐⭐⭐⭐ | Versionierte Images |
| **Größe** | ⭐⭐⭐ | Optimiertes Image |

=== Verweise

* **Implementiert durch:** <<decisions/ADR-003-use-docker.adoc,ADR-003: Use Docker>>
* **Beeinflusst durch:** <<07-quality-requirements,Qualitätsanforderung Reproduzierbarkeit>>
* **Verknüpft mit:** <<04-solution-strategy,Strategie Reproduzierbare Umgebung>>
* **Betroffen durch:** <<09-risks-and-constraints,Constraint Docker-Image-Wartung>>

== 5. GitHub Actions

=== Verantwortung

* **Automatisierte Ausführung** der Build-Pipeline
* **Change Detection** für effiziente Builds
* **Deployment** der generierten Artefakte

=== Pipeline-Struktur

[.text-center]
[plantuml]
----
@startuml
left to right direction

title GitHub Actions Pipeline

rectangle "detect-changes" as detect
rectangle "build-docs" as build
rectangle "deploy" as deploy

detect --> build : "wenn Änderungen erkannt"
build --> deploy : "wenn Build erfolgreich"

cloud "Artifacts" as artifacts
build --> artifacts : "upload"
deploy --> artifacts : "download"

@enduml
----

=== Jobs im Detail

[cols="1,2,1,1", options="header"]
|=== 
|Job |Verantwortung |Trigger |Output 

|**`detect-changes`** 
|Erkennt geänderte Dateien und bestimmt betroffene Builds 
|Push zu main 
|Filter-Ergebnisse (readme, architecture, site) 

|**`build-docs`** 
|Führt die relevanten Gradle-Tasks aus 
|Änderungen erkannt 
|Generierte Artefakte (build/) 

|**`deploy`** 
|Deployt Artefakte zu den Zielplattformen 
|Build erfolgreich 
|Deployte Dateien 

|=== 

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **Docker-Image** | → | Führt Container mit Build-Umgebung aus |
| **Gradle** | → | Ruft Gradle-Tasks auf |
| **SFTP** | → | Deployt zu Webspace |
| **GitHub API** | → | Deployt READMEs |
| **GitLab API** | → | Deployt READMEs |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Zuverlässigkeit** | ⭐⭐⭐⭐⭐ | Deterministische Ausführung |
| **Effizienz** | ⭐⭐⭐⭐ | Change Detection, Caching |
| **Sicherheit** | ⭐⭐⭐⭐ | Secrets Management |
| **Monitoring** | ⭐⭐⭐ | Logs, Status-Badges |

=== Verweise

* **Verknüpft mit:** <<04-solution-strategy,Strategie Change Detection>>
* **Verknüpft mit:** <<06-interfaces,Schnittstellen GitHub Actions → Docker/SFTP>>
* **Betroffen durch:** <<09-risks-and-constraints,Risiko GitHub Actions Limits>>

== 6. Deployment-Skripte

=== Verantwortung

* **Upload** der generierten Artefakte zu den Zielplattformen
* **SFTP-Deployment** für Website und Architektur-Dokus
* **GitHub/GitLab API** für README-Deployment

=== Technische Umsetzung

[cols="1,2,1", options="header"]
|=== 
|Skript |Zweck |Technologie 

|**`lftp` (in GitHub Actions)** 
|Upload zu SFTP-Server 
|SFTP-Client 

|**GitHub API Aufrufe** 
|Commit & Push von READMEs zu GitHub 
|GitHub REST API 

|**GitLab API Aufrufe** 
|Commit & Push von READMEs zu GitLab 
|GitLab REST API 

|=== 

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **GitHub Actions** | ← | Wird von Deployment-Job aufgerufen |
| **SFTP-Server** | → | Upload der Website/Architektur-Dokus |
| **GitHub Repo** | ↔ | Clone, Commit, Push für README |
| **GitLab Repo** | ↔ | Clone, Commit, Push für README |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Zuverlässigkeit** | ⭐⭐⭐⭐⭐ | Fehlerbehandlung, Retries |
| **Sicherheit** | ⭐⭐⭐⭐ | SFTP mit Passwort, API-Tokens |
| **Performance** | ⭐⭐⭐ | Paralleles Deployment |
| **Auditierbarkeit** | ⭐⭐⭐ | Logs, Git-History |

== 7. Environment Management

=== Verantwortung

* **Bereitstellung** von Umgebungsvariablen für Build und Deployment
* **Trennung** von öffentlichen und privaten Daten
* **Sicherheit** von sensiblen Informationen

=== Umsetzung

[cols="1,2,1,1", options="header"]
|=== 
|Umgebungsvariable |Zweck |Quelle |Sicherheitsstufe 

|**`SITE_*`** 
|Öffentliche Kontaktdaten für Website 
|GitHub Secrets 
|Mittel 

|**`CONTACT_*`** 
|Private Kontaktdaten für CV 
|`.env` + GitHub Secrets 
|Hoch 

|**`SFTP_*`** 
|SFTP-Zugangsdaten 
|GitHub Secrets + Variables 
|Hoch 

|**`GITLAB_TOKEN`** 
|GitLab API-Token 
|GitHub Secrets 
|Hoch 

|**`PROFILE_REPO_TOKEN`** 
|GitHub API-Token für Profil-Repo 
|GitHub Secrets 
|Hoch 

|=== 

=== Schnittstellen

| Schnittstelle | Richtung | Beschreibung |
|---------------|----------|--------------|
| **Gradle** | ← | Liest `.env`-Datei und System-Umgebungsvariablen |
| **GitHub Actions** | ← | Injektiert Secrets als Umgebungsvariablen |

=== Qualitätsanforderungen

| Anforderung | Priorität | Umsetzung |
|-------------|----------|------------|
| **Sicherheit** | ⭐⭐⭐⭐⭐ | Keine Secrets im Repository |
| **Trennung der Daten** | ⭐⭐⭐⭐⭐ | Öffentlich vs. privat |
| **Validierung** | ⭐⭐⭐ | Präfix-Prüfung (SITE_ vs CONTACT_) |
