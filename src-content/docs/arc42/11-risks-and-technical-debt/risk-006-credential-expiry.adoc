== RISK-006: Credential Expiry

=== Risk Statement

Because deployment jobs only run when their paths changed, and a skipped job shows as green, an expired or wrongly scoped credential may go unnoticed until a change needs it, leading to a failed deployment at that moment.

=== Assessment

[cols="1,3", options="header"]
|===
| Field | Value
| Likelihood | High
| Impact | Low
| Priority | Medium
| Timeframe | recurring
| Confidence | high
|===

The likelihood is high because the tokens expire by design. The impact is low because the published site keeps working; only updating it is blocked.

=== Mitigation

* GitHub and GitLab send an email before a token expires.
* After renewing a credential, the owner dispatches the `Check credentials` workflow, which checks every deployment credential without deploying, see xref:doc-06002-site-operations-runtime[DOC-06002].
* A test fails when the deployment uses a credential that the check does not cover.
* For the git targets, the check proves push permission on the repository, not a push to `main`. A branch rule or server hook added later still rejects the deployment while the check stays green. It shows with the next deployment that changes the target.
