== RISK-006: Credential Expiry

=== Risk Statement

Because deployment jobs only run when their paths changed, and a skipped job shows as green, an expired or wrongly scoped credential may go unnoticed until a change needs it, leading to a failed deployment at that moment.

=== Assessment

[cols="1,3", options="header"]
|===
| Field | Value
| Likelihood | High
| Impact | Low
| Priority | Medium
| Timeframe | recurring
| Confidence | high
|===

The likelihood is high because the tokens expire by design. The impact is low because the published site keeps working; only updating it is blocked.

=== Mitigation

* The `Check credentials` workflow proves every deployment credential weekly and warns 14 days before a GitHub token expires, see xref:doc-06002-site-operations-runtime[DOC-06002].
* A test fails when the deployment uses a credential that the check does not cover.
* The expiry of `GITLAB_TOKEN` is not checked and stays a calendar entry.
* GitHub disables scheduled workflows after 60 days without repository activity. The check then stops silently, and GitHub only sends a notice about it.
