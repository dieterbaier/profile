== Working agreements

Regeln, die entstanden sind, weil etwas schiefging. Keine Regel, die jemand
vorgeschlagen hat. Jeder Eintrag ist eine Zeile plus die Kosten, die ihn erzeugt
haben.

Der gerenderte deutsche Output wird bei jeder Änderung gegen einen Build des
vorherigen Standes verglichen.:: Kosten: ohne diesen Vergleich wären die
`{ui_cv_subtitle}`-Literale auf drei Seiten und die stillschweigende Whitespace-
Änderung jeder Seite unbemerkt live gegangen (#56, #55).

Vor dem Vergleich wird die Vergleichsmethode selbst verifiziert — `main` zweimal
bauen muss 0 Unterschiede ergeben.:: Kosten: ein stale Diff durch zsh
`noclobber` führte zu einer halben Stunde Fehlersuche an einem Fehler, der nicht
existierte (#49).

Eine Regel, die zweimal auf dieselbe Art verletzt wurde, wird von einem Test
erzwungen — nicht von einem Kommentar.:: Kosten: die Header-Falle (Leerzeile,
Kommentarzeile, fehlendes Leerzeichen nach dem Doppelpunkt) hat zweimal
zugeschlagen, bevor `test_link_registry_contains_only_attribute_entries`
entstand (#49, #51).

Ein Szenario entsteht mit dem Verhalten, nicht danach.:: Kosten: der Nachzug für
vier Slices kostete einen eigenen Slice (#65), und drei Ungenauigkeiten wären
beim Mitschreiben gar nicht erst entstanden.

Generierte Prosa macht keine Mengenaussagen.:: Kosten: „1 weiterer Artikel" wäre
falsch geworden, sobald die andere Sprache weniger Artikel hat — bemerkt vom
Owner im Review, nicht beim Schreiben (#57).

Fakten über fremde Laufbahn, Kunden und Projekte werden nicht erfunden, auch
nicht als „erster Wurf".:: Kosten: keine — die Grenze wurde beim CV vor der
Umsetzung gezogen (#56). Der Eintrag steht hier, damit sie gezogen bleibt.

Ein Defekt in einem fremden Projekt wird in dessen Quellen geprüft, bevor er
aufgeschrieben wird.:: Kosten: der `derived_from`-Befund war aus unserer Kopie
des Toolkit-Schemas abgeleitet und beschrieb einen Widerspruch, den das Toolkit
nicht hat. Ein `grep` in der fremden Datei hätte es widerlegt, bevor es im
Tagebuch stand (docs-as-code-toolkit#26, #75).

Eine Änderung, die ein Skript an einer Datei vornimmt, wird nachgelesen, bevor
sie als erledigt gemeldet wird — und jede einzelne Ersetzung trägt ein
`assert`.:: Kosten: von vier Ersetzungen an #79 griff eine nicht, ausgerechnet
die des Acceptance-Criteria-Blocks. Die Korrektur war gemeldet, während der
ausführbare Teil des Contracts weiter `401` und `.htpasswd` forderte — die
Grenze, die ADR-011 gerade abgeschafft hatte (#79, PR #92).

Ein neuer Build-Pfad wird aus einem sauberen Zustand geprüft, nicht aus dem, in
dem er entstanden ist.:: Kosten: die erste Konstruktion der Ausschlussliste war
strukturell unmöglich und trotzdem mehrfach grün, weil der Generator vorher von
Hand gelaufen war. Der erste saubere Build brach sie sofort (#77).

Eine Zusicherung in einem Record nennt den Mechanismus, der sie hält — oder sie
wird zur Absicht umformuliert.:: Kosten: drei Überspitzungen in zwei Pull
Requests, jede vom Owner gefunden: ein Artikel liege „in exactly one source
repository at a time" über einen nicht-atomaren Move, der Validator lehne falsche
`metadata_version`-Werte ab (er prüft `string`), und eine geteilte `id` *bedeute*
eine unterbrochene Promotion (sie kann eine Kollision sein) (PR #82).

Ein Szenario, das eine Zusicherung behauptet, deckt den Fall ab, in dem sie
bricht — nicht den, in dem sie trivial hält.:: Kosten: „An absent sibling leaves
the rest of the build alone" war grün, während ein vorhandener, unlesbarer
privater Checkout jeden `./gradlew`-Aufruf brach. Der fehlende Checkout ist der
Fall, in dem gar keine Selektion läuft; die Zusicherung war für den anderen
geschrieben. Gefunden im Review, nicht vom Test (#86, PR #96).

Ein neuer Task wird über den dokumentierten Weg ausgeführt, bevor er als fertig
gilt — nicht nur über den, auf dem er entstanden ist.:: Kosten:
`./build.sh buildSitePrivate` meldete einen fehlenden Sibling, den es auf dem
Host gab. Der Container ist der Weg, den CI geht, und er war kein einziges Mal
ausgeführt worden (#86).

Was CI ausführen soll, wird nicht ein zweites Mal aufgeschrieben.:: Kosten: die
Workflow-Datei zählte ihre Testtasks von Hand auf und war gedriftet — vier
registrierte Tasks fehlten dort, zwei Testdateien hatten gar keinen Task. 62
Testläufe waren unsichtbar, und die Pipeline blieb grün, weil ein Test, den
niemand ausführt, nicht scheitern kann (PR #96).
